# 香港金融科技行业转行概览

## 1. 一句话

香港金融科技的核心不是“做一个聊天机器人”，而是用技术改善支付、理财、保险、借贷、合规和客户服务，同时满足严格的监管与数据要求。

## 2. 香港本地场景

本地常见的金融科技方向包括虚拟银行、电子钱包、跨境支付、财富科技、保险科技和合规科技。香港市场小而国际，很多产品要同时面对粤语、普通话、英语用户，也要处理跨境资金、身份认证、反洗钱和客户尽职调查等流程。

因此，这个行业里的 LLM 应用通常不是“自由聊天”，而是“在明确边界内处理文档、回答政策问题、辅助人工审核”。模型输出需要可追溯、可审计，不能替代持牌人员的判断。

## 3. 常见岗位（非实时招聘）

- 业务分析师 / 产品分析师：把监管和业务需求翻译成流程与系统需求。
- 合规科技分析师：理解反洗钱、KYC、交易监控等流程，配置或评估系统。
- 数据分析师：用 SQL、Python 和报表分析客户、交易和运营数据。
- 后端 / 应用开发工程师：对接支付、账户、身份认证和内部系统 API。
- LLM 应用开发工程师：做文档抽取、知识库问答、客服辅助和审核摘要。
- 解决方案顾问：把产品能力映射到银行、保险或支付公司的实际流程。

## 4. 与 LLM 应用开发的结合点

1. **内部政策问答**：把合规手册、产品条款、操作流程做成可检索语料，回答时必须带章节来源。
2. **KYC / 开户文档抽取**：从公司注册文件、地址证明、财务报表中抽取字段，用 Pydantic 之类的数据契约校验。
3. **客服与争议摘要**：把多轮对话、交易记录和工单整理成结构化摘要，交给人工复核。
4. **可疑交易叙事辅助**：帮助分析人员整理时间线和证据，但不能自动做出可疑交易结论。
5. **多语言客户支持**：粤语、普通话、英语之间的问答和改写，需要保留术语一致性。

## 5. 建筑背景的切入路径

建筑行业常见的合同、招标文件、工程量清单、供应商资料和审批记录，本质上都是“多文档、强约束、需要留痕”的业务。这和金融科技的合规文档处理有相似之处。

可以优先瞄准“文档密集型”的 AI 应用岗位，而不是直接竞争纯算法研究岗位。你的优势是能理解复杂流程、跨团队协调和正式文件；需要补的是 Python、SQL、API、数据隐私和评测。

## 6. 需要补的技能

- Python 基础：文件读写、JSON、异常、函数、类型标注。
- SQL 与表格数据处理：能查数、清洗、对账。
- HTTP / API：理解请求、响应、鉴权和错误码。
- 结构化输出：Pydantic 模型、字段约束、校验失败处理。
- RAG：切片、检索、引用、无证据拒答。
- 隐私与合规：个人资料最小化、日志脱敏、人工复核。
- 评测：准备问题集，记录检索命中率和回答正确率。
